# FiRec 初期開発報告

## 対象

Git の最初のコミット「解析コア機能大体完成」より前に行った、要求整理・技術選択・構造設計・解析仕様の具体化をまとめる。

正確な日付や当時の未コミットファイルの差分は残っていないため、内容はこの会話で確認できる指示と、現在のリポジトリに残る構成から整理した。日付ではなく開発段階を中心に記載する。

## 1. 最初の要求

最初の目的は、TIFF 画像から次の2つの領域を取り出して比較することだった。

- radiation: フィルム上で黒くなっている照射野
- light: 照射野の境界に付けた点を基準に作成する光照射野

比較したい値は、各辺の長さ、面積、比率、中心位置、中心位置の差である。解析日時と画像名も保存し、後から一覧表示・検索・CSV 出力できるようにすることを目標とした。

さらに、Python と関連ライブラリで開発し、最終的には Windows のスタンドアロン実行ファイルとして利用する方針を定めた。

## 2. 技術選択

基本方針は「OpenCV で画像処理、PySide6 で GUI」だった。そこから必要な役割を補った。

| 役割 | 選択 | 初期段階での意味 |
|---|---|---|
| 画像処理 | OpenCV | 二値化、輪郭抽出、回転矩形の初期検出 |
| 配列計算 | NumPy | TIFF の画素値と幾何計算 |
| TIFF | tifffile | 画像読み込み、DPI メタデータ参照 |
| GUI | PySide6 | デスクトップ画面、ボタン、キー操作、画像表示 |
| プロファイル | pyqtgraph | 画像上の線に沿った画素値確認 |
| 保存 | sqlite3 | 解析結果の蓄積 |
| 出力 | csv | 表計算ソフト等への受け渡し |
| 配布 | PyInstaller | Windows 用実行ファイル |
| テスト | pytest / pytest-qt | 解析計算と GUI の動作確認 |

## 3. 構造設計

`src/firec` 配下を次の3領域に分けた。

```text
src/firec/
  core/
  gui/
  storage/
```

この分割の意図は、画像解析の計算を GUI から切り離すことだった。これにより、GUI のレイアウトを変更しても解析計算を再利用でき、計算部分だけをテストできる。

同時に `requirements.txt`、`pyproject.toml`、README、`tests/` を用意し、インストール・起動・テストの方法を決めた。

## 4. 自動検出の仕様

照射野の初期矩形は OpenCV で自動取得することにした。閾値は大津の方法を使い、二値化して暗い領域を検出する。

ただし、画像条件によって自動検出が外れる可能性があるため、次の扱いにした。

- 大津の閾値を仮の値として使う
- 自動取得に失敗しても、解析全体をエラー終了させない
- 仮の矩形を GUI に表示する
- ユーザーが閾値を変更し、矩形の変化を確認できるようにする
- 最終的な radiation はユーザーが確認して確定する

この仕様は、自動化の精度だけで完結させるのではなく、画像を見た人の判断をワークフローに組み込む設計である。

## 5. 矩形調整の仕様

照射野は回転矩形として扱う。light は radiation の確定後、その矩形と同じ角度・大きさを初期状態として表示する。

ユーザーが細かく調整できるよう、次の操作を検討・決定した。

- 矢印キーで上下左右へ移動
- Shift + 左右で回転
- Shift + 上で拡大
- Shift + 下で縮小
- 画像上のドラッグで移動・調整
- light では上下左右の辺を選択して位置を調整

矩形の点を個別に選択する案は、操作が複雑になるため採用しなかった。中心点は別色で表示し、radiation や light の中心を確認しやすくする方針にした。

## 6. GUI の仕様の具体化

初期案では、load、radiation、light、result をタブに分けることを検討した。その後、作業全体を `Analyse` と `Records` の2タブに整理した。

Analyse では、画像を左、操作 UI を右に配置する。load、radiation、light、result はタブではなく右側のフレームとして上から並べる。右側はスクロール可能にし、画像下には操作用のフレームを置く。

フレームの選択状態は解析ステップを表す。radiation を選択している間は、radiation 以外の操作を無効化する。load、radiation、light の完了時にはフレームにマークを付け、現在どこまで進んだかを画面上で確認できるようにする。

画像操作として、次を要求した。

- スクロールによる拡大縮小
- 画像上の空白部分のドラッグによるパン
- ダブルクリックによる拡大率と位置のリセット
- 画像と矩形を確認してから保存・解析へ進む

## 7. コア完成までの結果

GUI の詳細を詰める前に、まず次の解析基盤を実装した。

- TIFF 画像の読み込み
- 大津の閾値算出
- 暗い領域のマスク作成
- radiation の回転矩形検出
- 回転矩形の中心、頂点、辺長、面積の計算
- radiation と light の比較
- DPI がある場合の pixel から mm への換算
- プロファイル境界の検出に必要な計算

この状態が、2026-06-15 の「解析コア機能大体完成」コミットである。

## 8. 初期段階の評価

初期段階で、目的、技術、構造、ユーザー操作、解析の責任分担が定義できた。特に重要なのは、AI に「照射野解析ソフトを作る」とだけ伝えるのではなく、次のように要求を段階的に具体化した点である。

1. 何を比較するか
2. 自動処理をどこまで信用するか
3. 人がどこで確認・修正するか
4. 画像上でどう操作するか
5. どの情報を保存するか
6. 将来どの環境で使うか

この段階の完成度は、解析コアについては試作として高いが、GUI、実画像での精度評価、Windows 実機確認はこれからという評価になる。
