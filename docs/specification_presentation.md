# FiRec 再開発仕様書（発表用簡略版）

## 1. 作るもの

TIFF 画像を読み込み、画像上の放射線照射野と光照射野を比較して記録するデスクトップアプリを作る。

利用者は画像と矩形を見ながら、必要な箇所を手動で直してから結果を保存する。

## 2. 解決したい仕事

照射野の位置や大きさを画像から確認し、放射線照射野と光照射野のずれを記録したい。自動処理だけに任せるのではなく、利用者が結果を目で確認できるようにする。

## 3. 利用者の操作

1. TIFF 画像を開く。
2. 画像上の基準点を確認する。
3. 自動で表示された radiation の矩形を確認する。
4. 必要なら閾値や矩形を調整する。
5. radiation を確定する。
6. radiation と同じ角度の light 矩形を表示する。
7. light の辺を動かして画像に合わせる。
8. radiation と light の大きさ・中心・ずれを確認する。
9. 結果を保存する。
10. 過去の結果を表で確認し、必要なら CSV に出力する。

## 4. 画面の考え方

- 解析画面は左に画像、右に操作欄を置く。
- 解析は「画像読み込み → radiation → light → 結果」の順に進む。
- 現在の作業に関係ないボタンは使えないようにする。
- 画像を拡大・縮小・移動できるようにする。
- 画像上の矩形、中心、境界を見やすく表示する。
- 過去の記録画面では、画像よりも表を重視する。

## 5. 自動処理と人の確認

画像処理で radiation の仮の矩形を作る。大津の方法などで閾値を自動計算するが、自動結果を正解として固定しない。

自動結果が不十分な場合でも、利用者が閾値、位置、角度、大きさ、辺を調整できるようにする。最終的な確定は利用者が画像を見て行う。

## 6. 表示する結果

- radiation の大きさ
- light の大きさ
- radiation と light の比率
- radiation の中心
- light の中心
- 中心位置の差
- 解析日時
- 画像名
- pixel または mm 単位

TIFF に DPI 情報があれば mm に換算する。DPI がなければ pixel で結果を表示する。

## 7. 保存と再利用

- 解析結果をアプリ内に保存する。
- 保存済み結果を日時順の表で確認する。
- 必要な列だけ表示できるようにする。
- CSV として外部へ出力する。

## 8. 完成したと判断する条件

次の操作を、コードを変更せず画面から完了できること。

- TIFF を開く
- 照射野を確認・修正する
- 光照射野を確認・修正する
- 結果を表示する
- 結果を保存する
- 過去の結果を表で見る
- CSV を出力する

## 9. LLM に依頼するときに伝えるべきこと

このソフトを作るときは、単に「画像解析ソフトを作って」と依頼するのではなく、次の情報を順番に伝える。

- 誰が使うか
- どの画像を入力するか
- 何を自動化したいか
- 自動処理が失敗したときに人がどう直すか
- 画面で何を見たいか
- どの順番で作業するか
- 何を計算するか
- どこまで確認できれば保存するか
- 結果をどの形式で残すか

この程度まで自然言語で具体化できれば、LLM は画面構成、解析処理、保存処理、テスト項目へ分解して実装できる。

## 10. 発表での主張

この例が示すのは、非エンジニアが一度に完璧な設計書を書く必要はないということである。業務上の目的と、実際に利用者が行う操作を自然言語で伝え、試作画面を確認しながら仕様を具体化していけば、解析ソフトを段階的に形にできる。

ただし、LLM が実装できることと、業務上正しいことは別である。実データでの精度確認、利用者による操作確認、保存結果の確認、配布環境での動作確認は必要である。
