# FiRec 開発経緯と発表用整理

## この資料の目的

FiRec の開発初期から現在までについて、要求、技術選択、実装変更、完成度を発表用に整理する。

この資料は、現在のリポジトリ、Git 履歴、この会話で確認できる指示をもとに作成している。他の会話の本文はこの環境から直接取得できないため、そこに由来する内容は、現在の実装から確認できる範囲と推定を分けて扱う。

## 1. 開発全体の要約

FiRec は、TIFF 画像から放射線照射野（radiation field）と光照射野（light field）を設定し、両者の大きさ・中心位置・差異を算出して記録する解析ソフトである。

開発では、最初から完成した仕様を固定したのではなく、次の順に具体化した。

1. 解析対象と必要な比較項目を定義
2. OpenCV による大津の方法を初期値の取得に採用
3. ユーザーが画像を見ながら矩形を手動調整できる GUI を設計
4. 解析手順を段階的な画面構成に整理
5. DPI、SQLite、CSV、記録一覧など実運用に必要な機能を追加
6. 表示設定、説明、テストを追加して利用性を高めた

重要な設計方針は、「自動処理で初期値を出し、最終判断は画像を見たユーザーが行う」である。自動判定の失敗をエラーで止めるのではなく、調整可能な初期値として扱うことで、画像条件の違いに対応しやすくしている。

## 2. 時系列

### 開発初期: 目的と技術の決定

最初の要求は、画像上の radiation 領域と light 領域を鑑別し、矩形の辺長、比率、中心位置の差を求めて保存することだった。対象は TIFF 画像、GUI は PySide6、画像処理は OpenCV を中心にする方針とした。

決定した主な構成は以下の通り。

- Python: アプリケーション全体
- OpenCV: 二値化、輪郭・矩形の初期検出
- NumPy: 画像配列と数値処理
- tifffile: TIFF 読み込みとメタデータ参照
- PySide6: GUI
- pyqtgraph: プロファイル表示
- SQLite: 解析結果の保存
- CSV: 結果の外部出力
- PyInstaller: Windows 用のスタンドアロン配布
- pytest / pytest-qt: 自動テスト

この時点の完成度は、目的と主要技術が決まった段階であり、機能は未実装だった。

## 2.1 Git 履歴より前の開発過程

Git の最初のコミットは解析コアが大枠完成した時点である。そのため、それ以前の流れは会話上の要求と、現在のプロジェクト構成から復元する。ここでは厳密な日付ではなく、要求が具体化した順番を記録する。

#### 1. 解析対象と最初の目標を定義

最初に、フィルム画像上で黒くなった radiation 領域と、照射時に境界へ付けた点から作る light 領域を区別し、両者を比較したいという目標を設定した。

必要な結果として、次の項目を想定した。

- radiation と light の矩形
- 各辺の長さ
- radiation と light の大きさの比率
- それぞれの中心座標
- 中心位置の差
- 解析日時と画像名
- 後から確認・検索できる保存データ

また、最終的には Windows で Python 環境なしに動く実行ファイルにすること、解析結果は SQLite に保存し CSV に出力できることをプロジェクト目標として置いた。

#### 2. 使用ライブラリの候補を決定

画像処理は OpenCV、GUI は PySide6 を基本方針とした。補助ライブラリとして NumPy、TIFF 読み込み用の tifffile、グラフ表示用の pyqtgraph、テスト用の pytest / pytest-qt、配布用の PyInstaller を選んだ。

この段階では、ライブラリ名を先に増やすのではなく、必要な役割ごとに整理した。

- 画像配列・数値処理: NumPy
- 二値化・矩形検出: OpenCV
- TIFF とメタデータ: tifffile
- 画面・画像操作: PySide6
- 画素値のプロファイル確認: pyqtgraph
- 保存・出力: Python 標準の sqlite3 / csv
- 配布: PyInstaller

#### 3. プロジェクト構造と requirements を作成

Python の `src` レイアウトを採用し、`src/firec` の下を解析、GUI、保存に分ける方針を決めた。

```text
src/firec/
  core/       画像解析と幾何計算
  gui/        PySide6 の画面と画像操作
  storage/    SQLite 保存と CSV 出力
tests/        自動テスト
sample/       サンプル TIFF
```

この時点で、単一の `core.py` に全処理を集めるのではなく、将来 GUI や保存部分を変更しても解析ロジックを再利用できる形を選んだ。requirements と `pyproject.toml` を作成し、起動方法とテスト方法も定義した。

#### 4. 自動検出と手動確認の役割を分離

当初から、照射野を OpenCV で自動取得する方針を検討した。ただし、自動検出結果をそのまま正解とせず、次の流れにした。

1. 画像読み込み
2. 大津の方法で仮の閾値と矩形を取得
3. 自動検出が不十分でも処理を止めない
4. ユーザーが画像を見ながら矩形を調整
5. 調整後の radiation を確定
6. 同じ矩形を light の初期状態として調整

大津の方法で得た閾値は、後でユーザーが GUI 上で確認・変更できるようにする方針になった。つまり、OpenCV は「初期値を作る役割」、ユーザーは「画像を見て最終判断する役割」とした。

#### 5. 回転矩形と細かな調整方法を決定

照射野は画像に対して傾いている可能性があるため、矩形は回転を許可した。辺の角度は radiation を基準にし、light も同じ角度の矩形として扱うことにした。

調整方法については、画像上のドラッグとキーボード操作を組み合わせる方針を決めた。

- 上下左右の移動
- Shift + 左右で回転
- Shift + 上下で拡大・縮小
- 選択した辺の矢印キーによる微調整
- radiation 確定後の light の辺調整

途中で点単位の選択も検討したが、最終的には矩形全体と辺を対象にする方針へ整理した。中心点は選択状態を分かりやすくするため、黄色など別色で表示する考えを採用した。

#### 6. 画像確認を中心にした GUI の流れを決定

最初は load、radiation、light、result をタブに分ける案を検討した。その後、解析全体を `Analyse`、過去データを `Records` に分け、Analyse 内の load / radiation / light / result は右側のフレームとして縦に配置する構成へ変更した。

最終的な画面方針は次の通りである。

- 左側: 画像表示
- 右側: スクロール可能な操作 UI
- 右側上部: load、radiation、light、result のフレーム
- 画像下部: 移動・回転・拡大縮小の operation フレーム
- radiation などのフレームを選択すると、対応する操作だけ有効化
- Tab / Shift + Tab でステップを移動
- フレームに完了マークを表示
- 画像のスクロールでズーム、画像上のドラッグでパン、ダブルクリックで表示をリセット

この変更により、処理の順番を画面構成に反映しつつ、画像を常に見ながら作業できる設計になった。

#### 7. コア実装へ移行

要求が固まった段階で、まず GUI より先に画像解析と幾何計算を実装した。大津の閾値、暗部マスク、輪郭からの回転矩形、矩形の頂点・中心・辺長・面積、radiation/light の比較を独立した関数として整理した。
