# 他の会話に渡す開発履歴整理依頼

以下を、FiRec の別の会話の最後に貼り付けて使用する。

```text
この会話で行った FiRec 開発について、発表資料に使えるように整理してください。

次の形式で、日本語で簡潔にまとめてください。

1. この会話で私が出した主な要求
2. 要求が変化した順番
3. 採用したライブラリ・技術と採用理由
4. 実装した機能と変更したファイル
5. 不具合修正や設計変更
6. その時点での完成度
   - 実装済みか
   - 動作確認・テスト済みか
   - 実運用に残っている課題
7. 次の開発段階に引き継ぐべき内容

次のルールを守ってください。

- 会話に実際に書かれている内容と、コードから確認できる内容を優先する。
- 推測した内容には「推定」と書く。
- 実装したことと、話し合っただけのことを分ける。
- 日付が会話から分からない場合は無理に補わない。
- 発表時間は5〜7分を想定し、重要な判断だけを残す。
- 主題は「非エンジニアでも、コードを書かずに、自然言語で要求を整理しながら解析ソフトやGUIソフトを完成へ近づけられる。ただし検証は必要」である。

出力は次の見出しで作成してください。

## 時系列
## 使用決定ログ
## 実装変更ログ
## 完成度評価
## 残課題
## 発表で使う要点
```

## 統合時の使い方

各会話の出力を集めたら、次の順で整理する。

1. 同じ要求・変更をまとめる。
2. 会話の日付、ファイルの変更日、Git コミットを照合する。
3. 「決定」「実装」「検証」を別々の記録にする。
4. 実装されていない要望は、完成機能として書かない。
5. 最後に発表用の4段階へ圧縮する。

発表用の4段階は、原則として次の分類を使う。

- 解析基盤
- 画像を見ながら調整する GUI
- 記録と単位変換
- 利用性・説明可能性の向上
